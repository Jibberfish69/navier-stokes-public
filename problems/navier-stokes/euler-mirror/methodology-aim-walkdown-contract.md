# Euler Methodology-and-Aim Walkdown Contract

## Purpose

This is the primary working contract for the Euler mirror.

Its objective is not merely to count rewritten files or to maintain branch-local
audit scaffolding. Its objective is:

```math
\boxed{
\text{isolate each serious Navier-Stokes proof road into its methodology and
aim, then walk the incompressible Euler equations down that same road,
preserving the proof role honestly and recording the exact step where the
road survives, changes, or breaks.}
}
```

The actual Navier-Stokes theorem corpus on disk remains the authority for
recovering those roads. But the governing unit of execution is a conceptual
route, not a raw file census.

## Operational Unit

For this contract, a serious Navier-Stokes proof road is one that carries a
real theorem-bearing methodology. Each such road must be recovered in terms of:

1. its aim;
2. its mechanism;
3. its key propagated objects;
4. its bridge order;
5. its terminal contradiction, continuation, or closure classification.

Parent files are evidence for recovering that road. They are not the primary
deliverable by themselves.

## Hard Rules

1. Use the actual Navier-Stokes theorem corpus on disk as the source authority
   for reconstructing each road.
2. Isolate each serious conceptual branch into methodology and aim before
   judging Euler success or failure on that branch.
3. Walk the incompressible Euler equation down the same road with viscosity
   literally removed from both the governing PDE and every downstream proof
   packet.
4. Keep the parent proof method, theorem order, and burden structure as intact
   as honest mathematics allows.
5. When a road splits into subroads, preserve that split rather than flattening
   it into one generic summary.
6. When a step stops working, identify the exact mathematical break rather than
   replacing it with softer prose.
7. Build the Euler branch so that the theorem-facing files themselves read like
   actual Euler walkdowns of the Navier-Stokes routes.
8. Use audits, ledgers, and contracts only as secondary honesty tools rather
   than as the main deliverable.
9. Never confuse route-authoring completion with Euler global smoothness
   proved.

The current serious roads to be walked on Euler are:

1. `Euler membership / regularity mainline`
   Aim: define the Euler object by flux-volume and weak momentum-pressure
   fidelity, then prove any desired smoothness as a separate regularity upgrade.
   Mechanism: `Member_E = EVol + EMom`; flow-map, one-field coherence, and
   endpoint labels are optional regularity structures only. Pressure
   participation means incompressibility / normal compatibility, not one-field
   shear participation.
2. `Endpoint vocabulary demotion`
   Aim: keep `dead / blown / jump` from masquerading as primitive Euler class
   exits.
   Mechanism: use those labels only after a stronger regularity class has been
   explicitly defined; `dead` and `jump` remain live Euler nonsmoothness
   scenarios relative to those stronger classes.
3. `One-field regularity and receiver route`
   Aim: test whether one-field coherence can be preserved above Euler
   membership by Euler-native estimates.
   Mechanism: transported defect packets, coherence modulus, receiver-side
   lower-carrier control, and pressure recovery, all without viscous absorption.
4. `Positive-control four-bridge spine`
   Aim: force global regularity by control rather than contradiction.
   Mechanism: scale barrier, monotone functional, compactness/nonlinear
   closure, and gradient/continuation bridge.
5. `Transport-geometry / selector scaffold`
   Aim: organize torus-first geometry, selector bookkeeping, and downstream
   observability/readout structure.
   Mechanism: transported-phase-space selectors, balanced frames, cocycles,
   and selector-defect observability.
6. `Exact-potential / localized-projector / parabolic branch`
   Aim: convert witness data into readout/export structure.
   Mechanism: static diffusion, heat, Stokes, semigroup, and Carleman-style
   packets.
7. `Export / whole-space discharge branch`
   Aim: export low-mode or transported control into a downstream consumer
   theorem.
   Mechanism: low-mode strain, leakage control, and transport/export packets.
8. `Curvature / provenance support branch`
   Aim: feed scale or continuation burdens through geometry-sensitive
   quantities.
   Mechanism: curvature-to-scale or gradient-control provenance bridges.

These routes may be represented by more than one file each. File counts are
secondary evidence only.

## Completion Conditions

This contract is complete only when **all** of the following hold.

### W1. Route Extraction

Every serious Navier-Stokes proof road in scope has a branch-local Euler route
surface that states:

1. the road's aim;
2. its mechanism;
3. its key propagated objects;
4. its bridge order;
5. its terminal classification.

### W2. Euler Walkdown

Each route surface must actually try to walk Euler down the same road. This
means:

1. the governing PDE is the incompressible Euler equation;
2. the route does not silently import viscous, heat, Stokes, or parabolic
   closure as if it still belonged to Euler;
3. the walkdown reaches the first real surviving bridge or the first real
   failure bridge on that road.

### W3. Method Fidelity

Each Euler walkdown must preserve, as far as honest mathematics allows:

1. the parent proof method;
2. the parent theorem order;
3. the parent burden structure;
4. the parent role inside the larger route.

### W4. Exact Breakpoint Recording

If a route or subroute fails on Euler, the Euler file must name the exact
mathematical break:

1. the specific identity, estimate, coercive term, or continuation step that
   fails;
2. the exact place in the proof packet where it fails;
3. the strongest honest terminal classification visible from that break.

### W5. Route Classification

Each serious road must land in one of the following explicit branch-local
statuses:

1. survives on Euler;
2. survives with stated modifications;
3. blocked at an exact identified step;
4. quarantined as inherently parabolic unless rebuilt;
5. provenance-only and not a live mainline route.

### W6. Cross-Route Honesty

If one Euler route needs a supplier from another route, that dependency must be
spelled out theorem-locally. A downstream closure file may not pretend to stand
alone if it depends on an upstream route that this branch has not terminally
classified.

### W7. Theorem-Surface Standard

The primary deliverables must be theorem-facing Euler files. Audits, ledgers,
and contracts do not satisfy this condition by themselves.

### W8. Secondary-Tool Discipline

Audits, ledgers, and contracts may only serve to:

1. keep the branch honest,
2. record route classification,
3. record exact breaks,
4. track coverage,

and may not substitute for the route walkdown itself.

### W9. Theorem-Truth Discipline

No status surface may imply either of the following unless it has actually been
proved:

1. that the Euler theorem target is closed;
2. that route-walkdown completion implies Euler global smoothness.

## Honest Completion Rule

This contract may be marked complete only if every serious Navier-Stokes proof
road in scope has been walked far enough on Euler to yield either:

1. a real surviving Euler route, or
2. an explicit theorem-local obstruction with the exact broken bridge named.

If the branch instead contains only:

1. route inventories without Euler descent,
2. theorem summaries without walkdown,
3. audit scaffolding,
4. or a limited representative-file rewrite,

then this contract fails its completion check.
