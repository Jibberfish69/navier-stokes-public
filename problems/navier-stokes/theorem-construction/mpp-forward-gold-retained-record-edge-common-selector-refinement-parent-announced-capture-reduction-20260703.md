# Retained record-edge common selector refinement as parent-announced capture

## 1. Physical burden

The retained edge is one future-positive exact-projector work edge of the same
velocity field. The record is allowed to read a positive scalar later, but the
fluid packet that pays that positive read must already have a parent-known
address before the readout.

The common-selector question is therefore not whether a selector can be chosen
after the record has exposed a positive edge. That would be future argmax
selection. The physical question is whether the retained high packet, pressure
or strain coordinate, order-lock, polarity, and primitive channel were already
available as a finite stopped selector record before the record counted the
edge.

## 2. What existing stopped-selector work proves

The fresh common-selector repair proves the correct construction order for the
older fresh-source branch:

```math
\texttt{FreshCommonSelectorRefinementNoLoss.A}.
\tag{RCR.1}
```

It says that independently selected lower source, upper queue, and native
positive trilinear density cannot be identified after the fact. They must be put
on one stopped same-material transaction before the positive-part extraction is
used. That support is branch-specific, not a proof for arbitrary retained
record-menu edges.

The stopped-selector transition note proves the structural direction needed for
retained records:

```math
\text{finite parent-known stopped scores + first-exit reset}
\Longrightarrow
\text{announceable reset derivative endpoints}.
\tag{RCR.2}
```

It also records the obstruction. A selector chosen by future argmax or
best-descendant readout has no parent-known score, no announced first-exit time,
and no endpoint identity. This is exactly the wrong selection order for a
future-positive record edge.

The selector-stratum crossing note proves that unpaid chamber changes are not a
new physical source after a stopped selector packet exists:

The stopped-selector projection note proves the operator-level fact that a

The order-lock note identifies an unpaid order-lock gap as a submeasure of the
same selected density rather than a separate route. These are selector-motion
and selector-loss payment mechanisms once the selector has been parent-announced.

## 3. The retained-edge lower theorem

The remaining retained-edge theorem is:

```math
\texttt{RetainedRecordEdgeParentAnnouncedSelectorCapture.A}.
\tag{RCR.5}
```

Statement. For every arbitrary future-positive exact-projector record edge,
construct before positive record readout a finite parent-known stopped score
record

```math
\mathfrak R_e
=
(\mathfrak C_e,\sigma_e,\chi_e,P_e,\kappa_e)
\tag{RCR.6}
```

whose inequalities encode the carrier, selector cone, order-lock, polarity,
primitive channel, and chart/collar data of the same retained packet. The edge
is either captured by this stopped record before readout, or the uncaptured
part is routed to legal, stop, selector/reselection, order-lock, donor, chart,
collar, full-exchange, or Pack/Part/Field exit before it can be counted.

With that theorem, the existing stopped-selector surfaces supply the rest:


Here `OrderLockSelectedDensitySubmeasure.A' names the content already recorded

## 4. Proof of the strict reduction

Assume `(RCR.5)'. The record edge is now attached, before positive readout, to
one finite parent-known stopped score record. On intervals where that record
does not change, the stopped selector projection theorem makes the selected
coordinates bounded reads of the original same-material participation law. The
retained edge is therefore being carried by the same packet, not by a
post-readout selector.

When the selector chamber changes, the stratum-crossing BV theorem charges the
change to same-packet strain/exchange, viscous/radius service, legal, or stop.
When the order-lock changes, the order-lock alignment note routes the unpaid
gap into the same selected-density/first-ratio currency. When the aperture or
primitive channel changes, the stopped selector transition note makes the reset
an announced first exit, so the loss is a routed reset/service term rather than
a hidden change of payer.

Thus every retained positive part either remains on one stopped common selector
before readout or leaves through declared paid/stop/exit currencies. That is the
no-loss common-selector refinement required by
`RetainedRecordEdgeCommonSelectorRefinementNoLoss.A`.

## 5. Current truth state

This is a strict reduction. The repo has stopped-selector support after a
finite parent-known selector exists. It has an explicit obstruction to
future-argmax selection. It does not yet prove that every arbitrary
future-positive exact-projector record edge has a parent-announced stopped score
record before the record reads the positive edge.

The next unpaid physical object is therefore
`RetainedRecordEdgeParentAnnouncedSelectorCapture.A`: build the finite stopped
score menu from the same retained high packet and parent history before
positive readout, or route the uncaptured edge as paid, stopped, legal, or exit.
